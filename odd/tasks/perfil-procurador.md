# Perfil Procurador
New account role "procurador": supports 1 or 2 lawyers, sees only their semáforo, agenda, causas, hitos and cartera, and can enter hitos on their behalf.
Backend: /Users/marcelo/Projects/segal-case-tracker. Frontend: /Users/marcelo/Projects/segal-deudores-web.

## Specs
- S1. Request (Marcelo, 2026-11-16, verbatim): "hay que ver la creacion de un perfil de procurador, donde solamente pueden ver : Su semaforo, su agenda, causas, hitos y cartera". Scope chosen: "Las de los abogados que apoya". Actions (verbatim): "Debe poder ingresar los hitos de los abogados con los cuales trabaja, puede ser 1 o dos abogados a los que un procurador le puede hacer hitos".
- S2. Data: `lawyers.role = "procurador"` (new allowed value) and a link table `procurador_abogados (procurador_id, abogado_id, created_at)` (next migration), 1 or 2 active firm lawyers per procurador (0 or more than 2 rejected with 422 "Un procurador debe apoyar a 1 o 2 abogados."). A procurador is not a firm lawyer: never an owner, never in rosters, bono, rankings, traspaso destinations or Sysgal mapping lists.
- S3. Scope: a procurador's case scope = the union of the scopes of his linked lawyers, exactly as each lawyer's own scope is computed (`resolve_case_scope` / `case_ids_for_abogado`, including the scope cache, which must also be invalidated when the links change). Every endpoint that returns cases, plazos/semáforo, agenda, hitos or cartera data and respects the case scope must work for him with that union. He receives NO alerts/e-mails/Telegram (alerts stay with the lawyers).
- S4. Allowed screens and data (read): his lawyers' semáforo (the same semáforo views a plain lawyer gets for his own cartera), agenda, Causas list and case detail (incl. documents/PDF viewing the lawyer can see), Hitos, and Cartera (the lawyer-level cartera view, scoped to his lawyers). Everything else is 403 on the backend (not only hidden in the menu): admin panels, cuentas, credenciales, auditoría, traspaso, liberación requests, asignación, bono/liquidación, evaluaciones, renovaciones, reportes, Sysgal admin, Avance de cartera, Escritos generados, case mutations (semáforo override, notes, etc.).
- S5. Hitos: he can create hitos for one of his linked lawyers through the same create endpoint and validations as a lawyer (evidence required, duplicate/approved rules), choosing the lawyer when he has 2 (one → preselected); the hito belongs to that lawyer (`lawyer_id`, counts for that lawyer's bono) and records who entered it (`created_by_lawyer_id` or the existing equivalent; shown as "Ingresado por <procurador>" in the hito detail/list). He can see his lawyers' hitos and their evidence, edit/delete only hitos HE created while pending (same rules as a lawyer on his own), never approve/reject. Creating for a lawyer he does not support → 403 "Solo puedes ingresar hitos de los abogados que apoyas.".
- S6. Admin: in the accounts admin screen a role "Procurador" can be chosen when creating/editing an account, with a multi-select of 1-2 active firm lawyers ("Abogados que apoya"); the list shows them. Changing a procurador's lawyers takes effect immediately (scope cache invalidated). Blocking/unblocking works as for any account.
- S7. Frontend: the procurador's sidebar shows only Semáforo/Inicio (whatever screen holds the lawyer's semáforo), Agenda, Causas, Hitos, Cartera; direct URLs to other screens show the normal no-access state; the Hitos create form shows the "Abogado" selector (only his lawyers); the header shows "Procurador · apoya a <names>".
- S8. Strict TDD both repos (RED seen): scope = union of 1 and 2 lawyers (and changes when links change), 403 on every forbidden endpoint family (parametrized), hitos create for supported/unsupported lawyer (exact message), owner = lawyer + entered-by = procurador, no approve, no alerts to the procurador, admin create/edit with 0/1/2/3 lawyers (exact message), procurador excluded from rosters/bono/traspaso/Sysgal mapping; front sidebar items, route guards, hito form selector, admin form. Lawyers, auditors, supervisors and admins behave exactly as before (differential on scope for existing roles).
- S9. Follow-ups (Marcelo, 2026-11-16, verbatim: "en la lista de hitos, una columna \"Abogado\", para cuando el procurador apoya a dos" / "que al editar una cuenta se muestre el mensaje de error del servidor"): (a) the Hitos list shows an "Abogado" column (the hito's lawyer, `lawyer_nombre`) for a procurador who supports two lawyers (and keeps today's columns for everyone else); the Excel export includes it in that case. (b) Editing an account shows the backend error text (`detail`) exactly as returned, e.g. "Los abogados que apoya deben ser abogados activos del estudio."; the shared PUT helper must keep returning the same values and throwing for every other caller; only the thrown message gains the backend `detail` (same format the create path already shows). Tests: column present with 2 lawyers / absent with 1 and for lawyers; export column; edit panel shows the exact 422 text; existing callers of the PUT helper unchanged.
- S10. Accounts list "Traspasar cartera" button (Marcelo, 2026-11-16, verbatim: "este boton se ve muy feo ahi y tampoco les debe aparecer a los abogados bloquados"; screenshot: a black "Traspasar cartera" button rendered under each lawyer row, outside the row): move it into the row's actions area next to "Editar", same size and secondary/outline style as "Editar" (consistent with the app's buttons), never overflowing the row; show it only for active firm lawyers (role lawyer, is_firm_lawyer, is_active); never for blocked/inactive accounts, admins, auditors or procuradores. The "Traspaso de cartera" screen in the sidebar is unchanged (it still allows choosing a blocked origin). Tests: button present for an active lawyer, absent for blocked/inactive lawyer, admin, procurador; placed in the actions cell next to Editar.
