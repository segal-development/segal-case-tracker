# Matriz from Sysgal
Classify each case's matriz (M1 Baja / M1 Alta / M2 / M3) from Sysgal's own etapa (and later from Sysgal's matriz field), falling back to PJUD only for cases Sysgal does not have.
Backend: /Users/marcelo/Projects/segal-case-tracker.

## Specs
- S1. Problem measured in prod (2026-11-13): Causas chips show M1 Baja 2453, M1 Alta 0, M2 10097, M3 516, while Sysgal's own screen shows M1 Baja 7471, M1 Alta 1179, M2 2374, M3 1492. `app/services/matriz_classifier.py` documents that M1 Alta is unreachable from PJUD data (PJUD does not carry e.g. abandono 3 años vs 6 meses, excepciones de prescripción). Over the 4,649 cases linked to an active Sysgal causa, our matriz agrees with the matriz derived from Sysgal's etapa in only ~55 %: M2→M2 1646, M1 Baja→M1 Baja 753, M2 vs Sysgal M1 Baja 702, M2 vs M1 Alta 449, M2 vs M3 255, M1 Baja vs M2 118, M1 Baja vs M1 Alta 80. Top Sysgal etapas of our M2: INGRESO EXCEPCIONES DILATORIAS 1245, EXHIBICIÓN DOCUMENTOS 589, INGRESO EXCEPCIONES DE PRESCRIPCIÓN 279, INGRESO INCIDENTE DE NULIDAD 277, CAUSA ARCHIVADA 264, EMBARGO BIENES MUEBLES 199, INGRESO ABANDONO DE PROCEDIMIENTO 3 AÑOS 170. Sysgal etapas without a taxonomy row: "JUDICIAL" (9) and empty (4).
- S2. New precedence in the classifier: (1) a matriz sent by Sysgal for the causa (S5, when available); (2) Sysgal etapa: when the case is linked to an active, non-eliminated `sysgal_causas` row (`case_id`) whose `etapa` resolves in `matriz_clasificacion` (same normalization as the existing etapa lookup; proc_simple fallback "Juicio Ejecutivo Completo" as today, since Sysgal does not send the product), apply the existing `matriz_tramite_override` for that etapa + Sysgal `tramite` first, then the etapa row; `matriz_origen = "sysgal_etapa"`; (3) the existing PJUD path unchanged (pjud_etapa / pjud_descripcion / pjud_procedimiento / sin_detalle / no_mapeada). Several active Sysgal rows for one case: use the most recently updated (`sysgal_updated_at`, then highest id). An etapa that does not resolve (e.g. "JUDICIAL", empty) falls through to the PJUD path. The classifier stays pure (data passed in, no per-case queries); the bulk recompute preloads Sysgal etapa/tramite for all cases in one query.
