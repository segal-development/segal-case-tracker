# Avance de cartera from Sysgal statistics (bono V3)
Replace the manual weekly percentages of "Avance de cartera" with Sysgal's "Estadísticas de causas — Control de cartera y efectividad AT", freeze a monthly snapshot, and feed the bono V3 from each lawyer's monthly cobertura.
Backend: /Users/marcelo/Projects/segal-case-tracker. Frontend: /Users/marcelo/Projects/segal-deudores-web.

## Specs
- S1. Sysgal client: `estadisticas_cartera(desde, hasta)` → `GET /api_sync/estadisticas_cartera?desde=AAAA-MM-DD&hasta=AAAA-MM-DD` and `causas_sin_gestion(desde, hasta, abogado_id=None, desde_id=None, limite=500)` → `GET /api_sync/causas_sin_gestion`, same auth/retry/error rules as the existing `_get_json` (errors never carry the key or a body). Real payloads observed 2026-11-10 (desde 2026-11-01, hasta 2026-11-10): stats `{"desde","hasta","total_activas":12584,"total_morosas":38593,"gestionadas":5243,"sin_gestion":7341,"cobertura":41.66,"por_matriz":[{"matriz":"Sin clasificar","total":1,"gestionadas":1,"cobertura":100},{"matriz":"M1 Baja","total":7471,"gestionadas":3171,"cobertura":42.44},…],"por_abogado":[{"abogado_id":238,"nombre":"Luis Contreras Gonzalez","total":1057,"gestionadas":341,"cobertura":32.26},…]}` (16 rows); sin gestión `{"success","desde","hasta","data":[{"id_causa":1210,"rol":"C-4152-2018","tribunal":"1º Juzgado Civil de Puente Alto","abogado_id":83,"ultima_gestion":"2026-10-28 13:31:36"},…],"siguiente_desde_id":1703}`. Max range 182 days (Sysgal answers the effective desde/hasta). 400 invalid param.
- S2. Sysgal definitions (verbatim from ITDS, 2026-11-10): "Gestionada: causa activa con al menos un trámite con fecha de ingreso dentro del período, incluidos los que entran automáticamente desde el PJUD." "Activa y morosa: estado actual de la causa al momento de la consulta." "Abogado: el abogado actual de la causa. Una causa con más de un abogado cuenta para cada uno." "por_matriz incluye solo causas con matriz habilitada, por eso su suma no es igual a total_activas." "En por_abogado, total considera las causas ingresadas hasta hasta; en un período pasado, la suma puede ser menor que total_activas." "Sin filtro de abogado, el total del listado coincide con sin_gestion." We show Sysgal's numbers as they come; we never recompute them.
- S3. API (admin only, `require_admin`; lawyers/auditors 403):
  - `GET /api/v1/avance-cartera/estadisticas?desde&hasta` → live Sysgal stats (S1 shape) + each `por_abogado` row enriched with `lawyer_id` (from `sysgal_usuarios.lawyer_id`, null if unmapped). Validate range ≤ 182 days and desde ≤ hasta (400 "El rango máximo es de 6 meses." / "La fecha desde debe ser anterior a hasta."). Sysgal unavailable → 502 "Sysgal no respondió. Intenta de nuevo en unos minutos."
  - `GET /api/v1/avance-cartera/sin-gestion?desde&hasta[&abogado_id][&desde_id][&limite]` → one page passthrough (+ `lawyer_id`, + our `case_id` when `sysgal_causas.sysgal_id = id_causa` is linked).
  - `GET /api/v1/avance-cartera/snapshots/{periodo}` (periodo `AAAA-MM`) → the frozen snapshot or 404.
  - `POST /api/v1/avance-cartera/snapshots/{periodo}` → (re)take the snapshot of that whole calendar month (desde day 1, hasta last day) now; allowed only for a month that has ended; refused with 409 "La liquidación de ese mes ya está cerrada." if the bono liquidación for that periodo is closed (if the repo has a closed/locked state; otherwise always allowed). Audited like other admin writes.
- S4. Snapshot storage (new table, next migration after head): `avance_cartera_snapshots(id, periodo 'AAAA-MM' unique, desde, hasta, taken_at, payload JSON = the full Sysgal stats response as received, taken_by lawyer_id nullable)`; per-lawyer rows derivable from payload (no separate copy needed unless the bono needs an index). Scheduler: on day 1 (Chile) after 01:00, take the snapshot of the previous month once, on the VM maintenance worker (Sysgal only whitelists the VM IP) next to `_maybe_sync_sysgal_causas`; idempotent (skip if it exists); failures logged, retried next run, never crash the worker.
- S5. Bono V3: in the liquidación for periodo P, when a snapshot for P exists, the lawyer's `pct_cumpl` for tramo_v3 = the `cobertura` of the `por_abogado` row whose `abogado_id` maps to that lawyer (sysgal_usuarios.lawyer_id); a mapped lawyer absent from the snapshot → 0 with a visible note "Sin datos en Sysgal". When no snapshot for P exists, keep today's behaviour (manual `cumpl_sem1..5` sum) so months already paid are unchanged. Expose in the liquidación row the source (`fuente_v3`: "sysgal" | "manual") and the cobertura used. Do not change tramo bands or amounts.
- S6. Frontend "Avance de cartera" (admin): replaces the manual weekly grid entirely (remove the inputs and the save for cumpl_sem). Mirrors Sysgal's screen: Desde/Hasta (max 6 months, default first day of current month → today) + "Consultar"; cards Total Causas Activas, Total Causas Morosas, Gestionadas, Sin gestión, Cobertura (%, 2 decimals, es-CL format); table "Cartera por matriz" (Matriz, Total, Gestionadas, Cobertura); table "Cartera por abogado" (Abogado, Total, Gestionadas, Cobertura) sorted by total desc; button "Causas activas sin gestión del período (N)" opening a paginated list (ROL, Tribunal, Abogado, Última gestión; link to our causa when case_id) with filter by abogado and CSV download; a "Foto del mes" block: month picker, shows the frozen snapshot (taken_at) or "Sin foto", and "Tomar foto del mes" (POST) with confirmation. A short note under the cards: "Cifras de Sysgal. Gestionada = causa activa con al menos un trámite en el período, incluidos los que entran automáticamente desde el PJUD." Liquidación panel: V3 cell shows cobertura and "Sysgal" / "Manual" source. Errors shown as returned by the API.
- S7. Tests first (RED seen). Backend: client parsing incl. retries/no-secrets; admin-only (lawyer/auditor 403); range validation messages exact; enrichment lawyer_id/case_id; snapshot take/get/409 closed/only ended months/idempotent scheduler on day 1; bono V3 from snapshot vs manual fallback (month without snapshot unchanged), absent lawyer → 0 + note; Sysgal down → 502 message exact. Frontend: render with mocked fetch, range > 6 months blocked, sin-gestión list pagination + CSV, snapshot button, V3 source label; `tsc -b`, lint, vitest.
