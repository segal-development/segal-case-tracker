# Sysgal: bring each case's responsible lawyer (preparation, before Sysgal ships the endpoints)
Carla's decision: the real per-lawyer cartera comes from Sysgal (one responsible lawyer per case). Agreed precedence (Sept 2026): `Case.assigned_lawyer_id` override > Sysgal responsible > PJUD litigantes > nothing. Sysgal ships the endpoints in 1-2 business days; build against the announced contract, fully mocked in tests, nothing enabled in production until a human runs the report.

## Specs
- S1. Announced contract (Sysgal, 2026-11-09, verbatim): "GET /api_sync/causas: por causa, el ROL, el tribunal, el RUT del cliente, el abogado responsable (id y nombre), la etapa, el trámite y la fecha de actualización. Viene paginado por id_causa, con los parámetros desde_id y limite (máximo 500). La respuesta incluye siguiente_desde_id para pedir la página siguiente. También se puede filtrar por actualizado_desde y solo_activas. GET /api_sync/usuarios: id, nombre, perfil y estado de los abogados". Same API key (header X-API-Key), same base URL and IP as the existing `POST /api_sync/clientes_estado` (app/services/sysgal_client.py). We also asked for optional extras (id_causa, PJUD tribunal code, fecha desde que es responsable, estado, competencia, eliminada flag, correo in usuarios): parse them when present, never require them. Field names are not final: isolate the JSON→dataclass mapping in ONE function per endpoint so the real names are a one-line change; tolerate unknown fields.
- S2. Client: `SysgalClient.causas(desde_id=0, limite=500, actualizado_desde=None, solo_activas=None) -> page {items, siguiente_desde_id}` and `iter_causas(...)` that follows siguiente_desde_id until null/absent, with a hard page cap (e.g. 200 pages) and the same timeout/error handling style as `estado_por_ruts`; `SysgalClient.usuarios() -> list`. Never log the API key.
- S3. Storage (migration after the current head; check alembic/versions): `sysgal_causas` (sysgal_id unique, rol, rol_norm, tribunal, tribunal_codigo nullable, rut_cliente nullable, abogado_sysgal_id nullable, abogado_nombre nullable, etapa, tramite, estado nullable, competencia nullable, eliminada bool default false, responsable_desde nullable, sysgal_updated_at, case_id nullable FK cases ON DELETE SET NULL (indexed), match_method nullable ('rol+tribunal'|'rol+rut'|...), synced_at) and `sysgal_usuarios` (sysgal_id unique, nombre, perfil, estado, correo nullable, lawyer_id nullable FK lawyers — the mapping, set by a human or by an exact-email/normalized-name proposal, mapped_by nullable, synced_at). Add the cases FK table to case_merge's CHILD_TABLES_WITH_CASE_ID (re-point).
- S4. Sync service `sync_sysgal_causas(db, client, full=False)`: upsert usuarios; upsert causas (incremental with `actualizado_desde` = last max sysgal_updated_at unless full); match each causa to our Case: normalized ROL (reuse the repo's ROL normalization) + tribunal (normalize like the hitos tribunal key: fold °/º/ª, collapse spaces, uppercase; prefer tribunal_codigo vs courts.code when present), fallback ROL + client RUT among case_litigantes when the tribunal does not match uniquely; never guess when ambiguous (case_id stays null, counted). Returns stats {usuarios, causas, nuevas, actualizadas, calzadas, sin_calce, ambiguas}. Not scheduled yet (no worker hook) — the parent decides when.
- S5. Report (read-only), admin endpoint `GET /api/v1/sysgal/cartera/reporte`: `usuarios` [{sysgal_id, nombre, perfil, estado, lawyer_id, lawyer_nombre, propuesta_lawyer_id (exact email, else unique normalized-name match), }], `calce` {total, calzadas, sin_calce, ambiguas}, `por_abogado` [{lawyer_id, nombre, hoy (resolved_owner_by_case count), con_sysgal (count where the Sysgal responsible maps to this lawyer, among matched cases), diferencia}], and `ejemplos_sin_calce` (first 20). Plus `PUT /api/v1/sysgal/usuarios/{sysgal_id}` {lawyer_id|null} (admin) to set the mapping. Nothing here changes ownership.
- S6. Ownership precedence is NOT switched in this unit (no change to resolved_owner_by_case, alerts, cartera). Prepare a pure function `sysgal_owner_by_case(db) -> {case_id: lawyer_id}` (matched causas whose usuario is mapped, not eliminada) with tests, for the follow-up unit that switches precedence behind a setting.
- S7. Strict TDD, tests first, RED seen, all HTTP mocked (no network): client pagination (follows siguiente_desde_id, stops on null, page cap, limit max 500, filters passed), field mapping incl. optional extras and unknown fields, key never logged; upserts idempotent; matching (rol+tribunal with °/º, rol+rut fallback, ambiguous → null, eliminada); report numbers; mapping endpoint admin-only (lawyer/auditor 403); sysgal_owner_by_case. Existing tests keep passing (the case_merge metadata tests included).
- S8. Out of scope: switching ownership, scheduling, frontend, e-mail, Sysgal clientes_estado behaviour.
