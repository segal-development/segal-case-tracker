# Hitos: give plain lawyers the same view the public link had
Lawyers now sign in, so they register hitos from the app instead of the personal link. They must keep what the link gave them: every field and the evidence required, and the "Mis hitos enviados" summary (counts and totals).

## Specs
- S1. Request (L1, verbatim): "sus hitos ya no lo van a ingresar mas desde el link... peroooo hay que dejarles la misma vista que tenian, es decir agregar esto al formulario [screenshot: ~/hf1.png, the EVIDENCIA * file field with the help text 'PDF o imagen, hasta 15 MB. Sin evidencia el hito no se puede aprobar.'] y esto en la tabla [screenshot: ~/hf2.png, 'Mis hitos enviados': month, Descargar Excel, '6 hitos · 2 aprobados · 4 pendientes', cards TOTAL APROBADO $1.616 / PENDIENTE $3.232, 'Totales de Noviembre 2026. Los hitos rechazados no se cuentan.']. Esto es solo para los perfiles de abogados; para Carla, Melissa y yo dejar como esta."
- S2. Who: "plain lawyer" = `role == "lawyer"` AND NOT `can_manage_evaluaciones`. Carla and Marcelo are admins; Melissa is a lawyer with `can_manage_evaluaciones = true`. Frontend helper already exists: `esAbogadoComun(me)` in src/lib/hitoRoles.ts (do not change it).
- S3 (frontend-summary). A shared component `src/components/hitos/MisHitosResumen.tsx` renders the block of ~/hf2.png UNDER the title/month row: the counts line ("N hitos", "N aprobados" in verde, "N pendientes" in amarillo, "N rechazados" in rojo only when > 0), the two total cards (TOTAL APROBADO in verde with left border, PENDIENTE in amarillo) and the note "Totales de {Mes} {año}. Los hitos rechazados no se cuentan.". It receives the hitos of the month and the period. EXTRACT it from src/screens/RegistrarHito.tsx (the public link page already renders exactly this: the counts, `totales`, `totalBox`, `countChip`, `mesTexto`) and make RegistrarHito.tsx use the extracted component, so the two screens never drift. The public page must render exactly as before (its existing tests keep passing). In src/screens/Hitos.tsx show it for a plain lawyer only (`esAbogadoComun(me)`), above the "Hitos del período" table, using the hitos already loaded by `useHitos(periodo)` (a lawyer only receives her own). Totals use `valor_bruto` and `estado` (aprobado / pendiente / rechazado) the same way the public page does. The month selector and "Exportar a Excel" already exist in Hitos.tsx: keep them; make the button read "Descargar Excel" only if the public page's wording is the standard (do not rename if unsure).
- S4 (frontend-form). In src/components/hitos/RegistrarHitoForm.tsx add an optional prop `estricto?: boolean` for the authenticated mode ("auth"): when true, the form uses the STRICT rules of the public form (all fields required: tipo, fecha, RUT, ROL/causa, tribunal, procedimiento; evidence required with the type and 15 MB checks; the labels get the "*" and the help text of ~/hf1.png) while still posting to the authenticated endpoint. Reuse the strict schema in src/components/hitos/hitoSchemas.ts (`publicSchema`) instead of copying rules. When false/absent the form behaves exactly as today. The Hitos.tsx wiring (`estricto={esAbogadoComun(me)}`) is done by the parent, do NOT edit Hitos.tsx in this task.
- S5 (backend). `POST /hitos` (create_hito in app/api/v1/hitos.py): when the actor is a plain lawyer (role "lawyer" and not `can_manage_evaluaciones`; add a helper `_es_abogado_comun(actor)` next to `_is_admin`): run `_validate_public_form_fields(...)` (the same 422s as the public form: every field required, evidence present and non-empty, lengths) and create the hito with `origen=ORIGEN_FORMULARIO`, so the existing rule "a formulario hito cannot be approved without evidence" (`_requires_evidence`/`_SIN_EVIDENCIA_DETAIL`) applies. Admins, auditors and managers keep today's behaviour (evidence optional, origen manual). A plain lawyer still cannot set `lawyer_id` of someone else (existing 403).
- S6. Tests first (strict TDD, RED seen) in every task. Frontend: summary (counts, totals ignore rechazados, mes text, empty month, shown only for a plain lawyer in Hitos, public page unchanged), form (strict: evidence required and the field/help text visible; non-strict unchanged; the request carries the file). Backend: a plain lawyer without evidence -> 422; with everything -> 201 with origen formulario and `tiene_evidencia`; she cannot approve-by-route without evidence (existing); an admin without evidence still -> 201 origen manual; a lawyer with can_manage_evaluaciones unchanged; the length checks still apply; existing hitos tests keep passing.
- S7. Out of scope: the personal public links (stay as they are), the admin view, the liquidation, editing a hito, any other screen.
